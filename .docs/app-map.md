## 何をするアプリか

利用者に空席をランダムに割り当て、誰がどこに座っているかを共有する座席管理Webアプリのテスト版。座席から名前・ひとこと・今頑張っていることを確認できる。管理者はお題、テーブル、管理者アカウントを管理する。

基本の流れは「ログイン → 名前・ひとことを入力して席決め → 座席確認 → 帰社して席を解放」。管理者はログイン後に管理用画面へ進む。初期状態は2テーブル16席で、追加するテーブルは1台8席。

画面別の機能・処理の対応は [画面マップ](screen-map.md) を参照。

## 2つの動作方式

| 項目 | Java版 | Vercel用デモ版 |
|---|---|---|
| 画面 | `web/` | `vercel-demo/` |
| 処理 | 画面 → `web/app.js` の `api()` → `/api/...` → `SeatApp.java` | 画面 → `vercel-demo/app.js` の `api()` → `handle()` |
| データ | Javaプロセス内の `Store`。同じサーバーを使う利用者で共有し、再起動で初期化。 | `localStorage` の `seat-demo-v1`。同じブラウザ内で共有。 |
| ログイン状態 | Cookie `SID` とサーバーの `sessions` | タブごとの `sessionStorage` の `seat-demo-user` |
| 画面アクセス制御 | `SeatApp.page()` | `app.js` の `guard()` |
| 起動・配信 | ルートで `java SeatApp.java`。通常は `http://localhost:8080`。 | `vercel-demo` を静的サイトとして配信。 |

デモ版のAPI表記はJava版と対応する処理名であり、実際にサーバーへ通信するわけではない。別のPCとはデータを共有しない。

## 調査で押さえる現在の仕様

- IDとパスワードが空でなければログインできる。パスワードの保存・照合はなく、未登録IDはログイン時に作られる。初期の管理者IDは `admin`。
- 席決めは操作時点の全空席から1席をランダムに選ぶ。履歴や隣席の条件は考慮しない。着席済みなら再割り当てしない。
- 名前・ひとことは必須で100文字以内。今頑張っていることは任意で100文字以内。お題も必須で100文字以内。
- 席決め画面・座席画面は30秒ごとに情報を取得する。管理画面は初回表示と管理操作時に取得する。
- 画面には毎日0時の自動帰社とあるが、時刻による自動実行はない。管理者の手動リセットで全席を解除し、お題を選び直す。
- バーチャルオフィスの移動、通話、チャット機能はない。

## 調査の進め方

まずJava版かデモ版かを特定し、[画面マップ](screen-map.md) の該当画面・操作から関連ファイルと処理を読む。共通処理に原因がある場合は、その処理を使う別画面への影響も確認する。この資料は入口として使い、修正設計の前に最新コードとの一致を確かめる。
